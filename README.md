## 🛠️ Архитектура проекта и Спецификация Реактивных Потоков (RxJS)

В рамках данного домашнего задания все три задачи (Polling, Posts with Comments и Project Management Dashboard) объединены в **единый интерактивный веб-интерфейс (Mono-project)**. Вся асинхронная логика, комбинирование запросов и управление состоянием реализованы через библиотеку **RxJS (версия `7.8.0`)**.

### 📡 Спецификация реактивных модулей:

1. **Polling (Основное задание):** Реализован периодический опрос сервера через `interval(5000)`. Запросы отправляются через `ajax.getJSON()`. Тема письма (`subject`) динамически сокращается до 15 символов, а дата переводится в формат `ЧЧ:ММ ДД.ММ.ГГГГ`. 
   * *Контур безопасности:* Оператор `catchError` помещен внутрь подпотока `switchMap`. При падении сервера интервал **не умирает**, приложение маскирует ошибку под отсутствие новых сообщений и выводит на экран красный баннер предупреждения `⚠️ Сервер недоступен!`.
2. **Posts with Comments (Задача со звездочкой):** Реализована сложная реактивная сборка данных. Поток последних постов с `/posts/latest` разворачивается через `mergeMap`, после чего с помощью `forkJoin` запускаются параллельные подзапросы для скачивания последних комментариев к каждому посту на основе его уникального ID. В метод `.subscribe()` приходит уже полностью собранный, готовый к рендерингу массив объектов.
3. **Project Management Dashboard (Задача со звездочкой):** Написание кастомного **State Manager (Store)** на базе RxJS. Архитектура построена на паттерне *Redux*: отправка событий идет через `Subject (actions$)`, а накопление и мутация состояния — через связку операторов `startWith`, `scan` (эквивалент Reducer) и `share()`. Виджет статистики (слева) и виджет задач (справа) абсолютно изолированы друг от друга и синхронизируют данные исключительно через подписку на общий `store.state$`.
